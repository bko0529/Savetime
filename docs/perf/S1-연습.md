## 알게 된 점
1. **쿠키 같은 사용자별 헤더는 요청마다 붙여야 해요.** 처음에 `config.defaults.headers`에 `{{ cookie }}`를 넣었더니 사용자별 값이 안 채워져서 3,600건이 모두 401이었어요. 요청마다 `headers`를 붙여 해결했어요(YAML 앵커 `&pc`로 한 번만 적음)
2. **`ensure`(통과 기준)는 `plugins: ensure: {}`로 켜야 동작해요.** 켜지 않으면 기준을 넘어도 종료 코드가 0이에요
3. **Artillery 내장 Socket.IO 엔진 대신 `processor.mjs`에서 직접 연결했어요.** 병원 PC 인증이 httpOnly 쿠키(`st_pc`)라서 가상 사용자마다 다른 `Cookie` 헤더가 필요했기 때문이에요. 덕분에 연결 시간, 거절 이유, 끊긴 수를 직접 셀 수 있어요
4. **부하용 PC는 등록 API가 아니라 DB에 바로 만들어요.** 등록 API는 키 5번 실패 잠금과 병원당 PC 3대 제한이 있어서 부하 준비에 맞지 않아요(`npm run perf:pcs`)
5. **내 컴퓨터 한 대에서는 부하 도구와 서버가 CPU를 나눠 써요.** 1,000개까지는 여유가 있었지만, 5,000개는 기술정의서대로 클라우드의 별도 부하 서버에서 재야 해요
