# S7 배포 리허설 (T-11, CR-011)

- 날짜: 2026-11-11 · 담당: 백강욱
- 목적: Lightsail 에 올리기 전에 `deploy/` 설정을 `deploy/README.md` 순서 그대로 내 컴퓨터에서 띄워, 서버를 이어 붙였을 때 막히는 곳을 미리 찾는다
- 환경: MacBook (Docker Desktop, Compose 5.6). 도메인 대신 `localhost`(Caddy 내부 인증서), 데이터 서버 주소 대신 `host.docker.internal`. 실제 키 없이 임시 값만. 끝난 뒤 컨테이너·볼륨·임시 설정 파일은 모두 지움

| 순서 | 확인 | 결과 |
|---|---|---|
| 데이터 서버 | `deploy/data` 로 PostgreSQL·Redis (비밀번호, 사설 IP 에만 포트) | ✅ |
| 앱 서버 빌드 | `docker compose build` (server·web 이미지) | ✅ |
| 마이그레이션 | `docker compose run --rm server npm run migrate` | ✅ 0001~0012 적용 |
| 앱 서버 실행 | `/health` 200, `http://` → `https://` 308 | ✅ |
| 병원 웹 | `/` → `/hospital` 307 | ✅ |
| 관리자 화면 막기 | 앱 서버 `/admin` 404 | ✅ |
| 대원 API | 로그인 → 토큰 → `GET /me` 200 | ✅ |
| 실시간 | Caddy 를 거친 WebSocket(`/app`) 연결 (토큰 없으면 거절, 있으면 연결) | ✅ |

- 확인 못 한 것: 앱·관리자 서버를 **동시에** 띄워 관리자 → 앱 서버 실시간 전달 (한 컴퓨터에서 둘 다 80·443 을 써서). 이 동작은 서버 테스트(`관리자 서버에서 대원을 정지하면 main 서버에 붙은 그 앱이 강제 로그아웃된다`)로 확인돼 있고, Lightsail 에서 한 번 더 본다

## 찾아서 고친 것
1. **빈 값 뒤 설명이 값으로 들어감 (보안)**
   - `server.env.example` 의 `JWT_SECRET=                    # 무작위 32바이트…` 처럼 값이 빈 줄 뒤에 설명이 있으면, docker compose `env_file` 은 **설명 글을 값으로** 읽는다 (`KEY=abc   # 설명` 은 `abc` 로 잘 읽음)
   - `JWT_SECRET` 을 비워 둔 채 켜면 저장소에 공개된 설명 글(32자 이상)이 토큰 서명 키가 될 수 있었다. `KAKAO_REST_API_KEY` 는 실제로 설명 글이 키로 들어가 있었다
   - 고침: 템플릿의 설명을 모두 윗줄로 옮김. 서버는 `#`로 시작하는 값이 있으면 **이름만 알려 주고 켜지지 않음** (`config.ts`, 테스트 `config.test.ts`). 리허설에서 옛 설정 파일로 켜면 멈추고, 새 템플릿으로는 켜지는 것까지 확인
2. **관리자 허용 IP 형식 차이**: Caddy 는 CIDR 을 받지만 서버(`ADMIN_ALLOWED_IPS`)는 정확한 IP 만 받는다 → `deploy/README.md` 체크리스트에 적음

## Lightsail 에서 할 때 다른 점
- `host.docker.internal` 대신 데이터 서버 **사설 IP**, `localhost` 대신 실제 도메인 (DNS 가 먼저 서버를 가리켜야 Let's Encrypt 인증서가 나온다)
- 데이터 서버 방화벽: 5432·6379 는 앱·관리자 서버 사설 IP 만
- 자동 스냅샷 켜기 (QUR-010, CR-012)
