## 1. 한 줄 원칙
> **바꾸는 일은 REST API로, 알려주는 일은 웹소켓으로. 이벤트는 "무언가 바뀌었다"는 벨이고, 내용은 REST로 가져온다.**

식당에 비유하면 호출 벨은 "음식 나왔어요"까지만 알려주고, 음식(환자 정보)은 카운터에서 직접 받아 가는 방식이에요. 벨 기록에 음식이 남지 않으니 개인정보가 안전해요.

| 하는 일 | 통로 |
|---|---|
| 요청·승인·거절·확정·도착·취소 | REST API (`version` 확인 · 확정은 중복 방지 키) |
| 새 요청 왔어요 · 승인됐어요 · 2분 지났어요 | 웹소켓 이벤트 |
| 앱이 꺼져 있거나 화면이 꺼짐 | FCM 푸시 (iOS는 FCM → APNs) |

## 2. 연결 구조 (Socket.IO 4, 서버 1대)

| 네임스페이스 | 누가 | 인증 | 방 |
|---|---|---|---|
| `/app` | 구급대원 앱 | `auth.token` (accessToken) | `paramedic:{id}`, `team:{teamId}` |
| `/hospital` | 병원 웹 | 등록 PC 쿠키 `st_pc` (서버가 PC 식별) | `hospital:{id}` (등록 PC 전체), `hospital:{id}:on` (알림 켠 PC만) |
| `/admin` | 관리자 웹 | `auth.token` (관리자) | `admin` |

- **ping 5초, 응답 대기 5초** → 끊김을 10초 안에 감지 (INR-003). 앱은 "연결 끊김 · 다시 연결 중", 병원 웹은 빨간 배너.
- **방 들어가기·나가기는 서버가 REST 처리와 같은 자리에서 바로**: 팀 참여·초대 수락 → `team:{id}` join + `team_member.joined_seq` 기록 / 근무 종료 → leave / 알림 켜기 성공 → `hospital:{id}:on` join / 근무 종료·ack 없음 → leave.
- **요청 대상 병원** = `hospital:{id}:on` 방에 소켓이 1개 이상 + 계정 활성 + 잠시 요청 중지 아님 (SFR-109·117·139).
- 토큰 만료 → `connect_error: TOKEN_EXPIRED` → refresh 후 재연결. 정지·로그아웃·PIN 5회 → `account.force_logout` 후 연결 끊기 (10초 안, SER-016). 키 폐기·만료·PC 해제 → `pc.revoked` 후 끊기.

### 병원 웹 알림 켜기 자동 복구
- 탭을 유지한 채 연결만 끊겼다 붙음 → 웹이 메모리에 가진 `shiftId`로 `alarm.resume` → 서버가 같은 PC·같은 근무인지 확인 후 `:on` 방에 다시 넣음.
- 새로고침·다시 열기 → `shiftId`가 없으니 복구 안 됨 → "알림 켜기를 다시 누르세요" (브라우저 소리 정책, SFR-117·D-96).

## 3. 순서 보장과 놓친 이벤트 다시 받기 (앱 · 관리자) ⭐

```
[서버, 상태를 바꾸는 트랜잭션 안]
 1) 상태 변경 + transport_status_history
 2) pg_advisory_xact_lock(7401) → event_log INSERT (seq 발급)   ← 커밋 순서 = seq 순서
 3) COMMIT
 4) 커밋 뒤에 방으로 전송 (롤백된 이벤트는 절대 안 나감)

[앱, 연결·재연결 직후]
 1) 실시간으로 오는 이벤트는 일단 큐에 모음
 2) emit('sync', { lastSeq })
 3) 서버: seq > max(lastSeq, 팀 joined_seq) 이고 내 방(paramedic·현재 team)인 것을 순서대로 다시 보냄
         lastSeq가 없거나 24시간보다 오래됐으면 snapshotRequired=true
 4) ack 받으면 큐 처리. snapshotRequired면 GET /transports/current로 전체를 받음
 5) 같은 대상(entityType+entityId)은 entityVersion이 더 큰 것만 반영 · 같은 seq는 무시
```

- 다시 받은 `request.approved`에는 `afterReconnect: true` → "연결 복구 후 새로 확인된 승인"으로 진동·소리 (SFR-110·130).
- 앱 재실행으로 전체를 새로 받은 경우: 앱이 기기에 저장해 둔 직전 승인 목록과 비교해 새 승인이 있으면 같은 경보 (SFR-133).
- **병원 웹은 다시 받기를 하지 않음**: 재연결되면 무조건 `GET /hw/requests` + `GET /hw/incoming`. 이벤트 기록에서 닫힌 요청이 되살아날 일이 없음 (SER-014).
- 남은 시간은 `serverNow`와 `respondUntil`의 차이로 계산 (폰 시계 차이 무시, SFR-110).

## 5. 푸시 규칙 (FCM · iOS는 APNs 경유)
```
이벤트가 '푸시 대상'(4-1 표 ✅)이면 팀원마다:
  소켓 연결 + 앱이 화면에 보임 → 웹소켓만 (앱이 직접 진동·소리)
  그 밖 (앱 꺼짐·화면 꺼짐·백그라운드·끊김) → 웹소켓 + FCM 푸시
```
- **문구에 환자 정보 금지** (잠금 화면에 보임): `B대학교병원 승인 · 9분`, `1분 뒤 승인이 해제돼요`, `B대학교병원이 승인을 취소했어요`.
- **보내는 형식**: notification 메시지(데이터 전용 아님). Android = 중요도 높음 채널 + 진동 패턴, iOS = `aps.sound: default`. 앱이 화면에 있을 때 직접 내는 소리는 무음 스위치를 따르는 설정(iOS ambient) → iPhone 무음 모드면 진동만 (SFR-130, COR-014). '중요 알림'(critical) 권한은 쓰지 않음.
- **푸시를 눌러 앱을 열 때 잠금 건너뛰기**: 팀에 진행 중 이송이 있을 때만 (SFR-150). 초대·가입 결과 푸시는 잠금 화면을 거침.

## 6. 서버 타이머 (서버 시각, 재시작해도 DB에서 다시 건다)

| 타이머 | 기준 | 시점 | 하는 일 | 취소되는 경우 |
|---|---|---|---|---|
| 받았음 확인 | request.new 전송 | +5초 | ack 없으면 `delivery_failed` | - |
| 응답 제한 | `request_round.respond_until` | +2분 | 대기 → 만료, 역방향 연쇄로 예비 전환 판단 | 그 회차가 끝남 |
| 해제 경보 | 회차 `sent_at` | +4분 | 미확정 유효 승인 1곳 이상일 때만 `approval.expiring` | 확정·새 회차·취소·예비 전환 |
| 승인 해제 | `approval_valid_until` | +5분 | 승인 → 닫힘(5분), 이송 건 예비 추천 | 확정·새 회차·취소 |
| 경로 안내 담당 | 확정 시각 | +10초 | 운전 단말 응답 없으면 확정한 대원 단말로 | 운전 단말 응답 |
| 도착 예상 갱신 | 이동 중 | 1분마다 | 담당 단말 위치로 길찾기 → `transport.eta`, `incoming.updated` | 도착·취소 |
| 초대 만료 | `team_invite.expires_at` | +5분 | 만료 → `team.invite_result{expired}` | 수락·거절 |
| 자동 근무 종료 | 근무 시작 | +14시간 | 진행 중 이송 없으면 팀에서 빠짐 | 근무 종료 |
| 활동 없음 자동 종료 | `transport.last_activity_at` | +2시간 | 이송 건 취소(`auto_inactive`) | 활동마다 다시 계산 |
| 요청 중지 알림 | `hospital.paused_at` | +2시간 | `hospital.pause_reminder` | 해제 |
| 수용 불가 창 | 도착 시각 | +10분 | 이후 '수용 불가' 불가, 병원·팀 연결 지움 | - |
| 직전 환자 정보 | 도착·취소 시각 | +10분 | 팀 작성 중 정보 비우기 | 새 요청 |
| 확정 병원 열람 끝 | 도착 시각 | +1시간 | 환자 정보 열람 차단 (조회 때 판정) | - |

- 타이머는 메모리(setTimeout)로 돌리고, 실행할 때는 **반드시 상태 전이 함수를 거친다**. 이미 다른 이유로 상태가 바뀌었으면 함수가 거부하니 그냥 끝냄(멱등).
- 서버 재시작 → DB의 시각 칸을 읽어 다시 걸고, 이미 지났으면 바로 실행.

## 8. 테스트 체크리스트 (S1·S3)
- [ ] 병원 웹 승인 → 앱에 1초 안 표시 (S1 성공 기준)
- [ ] 앱 비행기 모드 30초, 그사이 승인 1건 → 해제 후 `sync`로 받고 진동 (`afterReconnect`)
- [ ] 같은 승인 이벤트가 실시간·다시 받기로 두 번 와도 한 번만 반영, 오래된 이벤트가 최신을 덮지 않음
- [ ] 앱 완전 종료 → 승인 → 푸시 (Android · iPhone, iPhone 무음 모드면 진동만)
- [ ] 병원 PC 2대 중 1대만 알림 켬 → 그 PC만 `request.new` 받음, 전달 1곳으로 셈
- [ ] 병원 탭 잠듦(ack 없음) → 5초 뒤 '7곳 전달', 그 PC에 `hospital.alarm_off`
- [ ] 병원 PC 재연결 → 다시 받기 없이 전체 새로 받기, 닫힌 요청의 환자 정보 안 보임
- [ ] 병원 PC 2대 동시 승인 → 한쪽만 성공, 다른 쪽 `request.changed`로 "박서연 님이 승인함"
- [ ] 서버 재시작 → 진행 중 2분·4분·5분 타이머 이어서 동작
- [ ] 계정 정지 → 10초 안 앱 로그아웃 + 소켓 끊김
- [ ] 네트워크 끊김 → 10초 안에 "연결 끊김" 표시
