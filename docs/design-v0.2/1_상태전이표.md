## 0. 원칙
- 상태를 바꾸는 코드는 반드시 `transitionTransport()` / `transitionHreq()`를 거친다. **표에 없는 전이는 전부 거부** (`INVALID_TRANSITION`).
- `transport.version`은 이송 건 행이 바뀔 때만 +1. 병원 응답은 `hospital_request.version`만 올린다 → 다른 병원이 승인해도 대원의 확정이 버전 충돌로 실패하지 않음.
- 시간은 모두 서버 시각. 확정 판정 시각은 "첫 시도가 서버에 도착한 시각"(SFR-111) — 중복 방지 키로 다시 온 요청은 첫 시각을 씀.

**표에 없는 부록 A 행 (상태가 안 바뀜)**: A22 도착·취소 뒤 10분 안 새 요청 = 새 이송 건 `CREATE` / A25 무효 승인 확정 = 오류(`APPROVAL_CANCELLED`·`APPROVAL_EXPIRED`), 요청 중 유지 / A26 앱 재실행 = 변화 없음(`GET /transports/current`) / A27 진행 중 새 요청 = `ACTIVE_TRANSPORT_EXISTS` / A30 통신 두절 중 기록 = `OFFLINE_QUEUEABLE`(전화 확인 결과·거절·도착·오프라인 예비 추천 건)만 단말에 보관 → 복구 때 같은 함수로 순서대로 적용, 충돌은 버전으로 판정. 확정·취소·목적지 변경·요청은 오프라인에서 막는다.

**취소 사유 7종** (`cancel_reason`): `user`(이송 취소) · `auto_inactive`(2시간 활동 없음) · `duty_end` · `logout` · `withdrawal` · `suspended`(팀의 마지막 대원) · `offline_superseded`(통신 두절 중 만든 건이 복구 때 서버의 다른 진행 중 건과 겹침 → 오프라인 건은 이력으로, SFR-099·A30). 사람 취소(`user`)만 version 필수.
**도착 방법 4종** (`arrival_method`): `button` · `menu` · `hospital` · `finish_previous`. 병원 웹 '도착 확인'으로 바로 도착(위치 있는 건, 200m 안)은 서버 판단이라 version 없이, 위치 없는 건은 대원이 확인 요청에 답해 `hospital`로 보내며 version 필수.
**생성**(`CREATE_*`)은 version 대신 앱이 만든 UUID로 중복을 막는다.

**이동 중 다시 요청·목적지 변경의 대상이 0곳이면**: `NO_REQUEST_TARGET`(422)로 이동 중에 머문다(이동 중 → 예비 추천 길은 없음). 앱은 "요청할 병원이 없어요 — 경로 안내를 계속하거나 '이송 취소' 후 새로 요청하세요"를 보여준다. 새로 요청할 때 대상이 0곳이면 생성 단계에서 예비 추천으로 간다.

## 3. 연쇄 (한 트랜잭션)

### 3-1. 이송 건 사건 → 병원 요청
| 이송 건 사건 | 병원 요청에 일어나는 일 |
|---|---|
| 병원에 요청 (대상 1곳 이상) (`CREATE_WITH_TARGETS`) | 새 회차 병원 → `SEND` |
| 승인 병원 1곳 선택 (`CONFIRM`) | 고른 병원 → `CONFIRM_THIS`<br>open [waiting·approved] → `OTHER_CONFIRMED` |
| '기다리지 않고 예비로' (`GO_FALLBACK`) | open [waiting·approved] → `TRANSPORT_FALLBACK` |
| 요청 후 5분 선택 없음 (`APPROVAL_WINDOW_ENDED`) | approved [approved] → `APPROVAL_TIMEOUT` |
| '반경 넓혀 다시 요청' (`EXPAND_ROUND`) | 새 회차 병원 → `SEND` |
| '다시 요청' (`RE_REQUEST`) | 새 회차 병원 → `SEND` |
| '목적지 변경' (길게 누름·사유) (`CHANGE_DESTINATION`) | confirmed [confirmed] → `DEST_CHANGED`<br>새 회차 병원 → `SEND` |
| 도착 처리 (`ARRIVE`) | confirmed [confirmed] → `ARRIVE` |
| '이전 이송 끝내기' (`FINISH_PREVIOUS`) | confirmed [confirmed] → `ARRIVE` |
| 이송 취소 · 자동 종료 · 마지막 대원 퇴장 (`CANCEL`) | open_or_confirmed [waiting·approved·confirmed] → `TRANSPORT_CANCEL` |

### 3-2. 병원 요청 변화 → 이송 건 (`transportEventAfterHreqChange`)
| 조건 | 이송 건 사건 |
|---|---|
| 이동 중 + 확정 요청이 승인 취소 | `CONFIRMED_HOSPITAL_CANCELLED` (경보, 다시 요청 버튼) |
| 요청 중 + 현재 회차 대기 0곳 · 유효 승인 0곳 | `NO_OPEN_REQUEST` (사유: 마지막 사건이 전달 실패면 none_delivered, 2분이면 expired_no_approval, 승인 취소면 approvals_cancelled, 그 밖은 all_rejected) |
| 요청 중 + 승인 취소, 남은 요청 있음 | `APPROVAL_CANCELLED_OPEN_REMAIN` |
| 요청 중 + 승인·거절·요청 중지 | `HOSPITAL_RESPONDED` |
| 5분 해제(`APPROVAL_TIMEOUT`) | 없음 — 5분 타이머는 이송 건 `APPROVAL_WINDOW_ENDED`를 먼저 부르고, 그 연쇄로 승인 요청을 닫는다 (두 길로 처리하지 않음) |

### 3-2-1. 행 잠금 순서 (교착 방지)
모든 트랜잭션은 **transport를 먼저 `FOR UPDATE` → 그다음 hospital_request(id 오름차순)**. 병원 웹 API(승인·거절·승인 취소·도착 확인·수용 불가)도 요청 id로 `transport_id`를 먼저 찾아 transport부터 잠근다. 대원 '도착'과 병원 '승인 취소'가 동시에 와도 한쪽이 기다렸다가 바뀐 상태로 판정받는다(먼저 온 것 하나만 반영, SFR-160).

### 3-3. 제외 병원 (SFR-086 한 규칙)
병원 웹 거절(요청 중지 자동 거절 제외) · 승인 취소 · 전화 확인 거절 · 목적지 변경 전 병원 · 10분 안 직전 이송의 수용 불가 병원 → `excluded_hospital`에 추가. 새 회차를 만들 때 서버가 이 표를 빼고 대상을 계산.

## 5. 서버 코드에서 쓰는 법
```ts
// 틀: tx { 행 잠금(FOR UPDATE) → transition() → 저장(version+1) + 이력 → 연쇄 → 역방향 연쇄 → event_log(outbox) }
await db.tx(async t => {
  const tr = await t.one('SELECT * FROM transport WHERE id=$1 FOR UPDATE', [id]);   // ① 항상 transport 먼저
  const target = await t.one(`SELECT h.status, h.closed_reason, r.approval_valid_until
     FROM hospital_request h JOIN request_round r ON r.id = h.round_id WHERE h.id=$1 FOR UPDATE`, [reqId]);
  const { to, history } = transitionTransport(tr.status, 'CONFIRM', {
    now: firstAttemptAt, version: tr.version, clientVersion: body.version,
    target: { status: target.status, closeReason: target.closed_reason, approvalValidUntil: target.approval_valid_until },
  });
  await t.none('UPDATE transport SET status=$1, version=version+1, confirmed_hospital_id=$2, confirmed_at=now(), departed_at=COALESCE(departed_at, now()) WHERE id=$3', [to, hospitalId, id]);
  await t.none('INSERT INTO transport_status_history(transport_id, from_status, to_status, event, reason, at) VALUES ($1,$2,$3,$4,$5,$6)', [id, history.from, history.to, history.event, history.reason, history.at]);
  // CASCADE.CONFIRM: 고른 병원 CONFIRM_THIS, 나머지 대기·승인 OTHER_CONFIRMED → 각각 transitionHreq() + 이력
  // event_log에 기록 → 커밋 후 전송 (실시간 설계 v0.2)
});
```
