## 1. 전체 구성

```
 [구급대원 앱]  Lovable 웹앱 (휴대폰 브라우저, CR-010)
      │  REST (HTTPS)  +  Socket.IO /app (WSS)
      ▼
 [앱 서버]  1대 (v0.11, CR-011) · Caddy(HTTPS·도메인 1개) → 웹(Next.js 16) + 서버(Node.js 24 · Express 5 · Socket.IO 4)
               │
               ├─▶ Redis 7  : 서버 간 실시간 연결 공유 · 작업 큐(타이머·수집) · 요청 제한
               ├─▶ PostgreSQL 16 (1대 + Lightsail 자동 스냅샷 매일)
               └─▶ 객체 저장소 : 공무원증 사진(암호화)
      ▲  REST + Socket.IO /hospital
 [병원 웹]  Next.js 16 (/hospital)

 [관리자 서버]  따로 1대 · admin. 도메인 · 접속 IP 제한(Caddy + 서버 ADMIN_ALLOWED_IPS) · 같은 이미지(APP_ROLE=admin)로 /admin 화면 + 관리자 API만 켬 (T-11)
      └─▶ 같은 PostgreSQL · Redis. 실시간은 '보내기 전용': 대원 정지·PC 해제·가입 결과를 Redis 어댑터로 앱 서버의 연결에 보냄 (타이머 작업은 안 돌림)

 외부: 공공 응급의료 API(전국 17개 시·도) · 카카오 길찾기·주소 · FCM(서버 → 구글 → 폰, 별도 푸시 서버 없음) · AI API(일지 정리, 서버만)
 도메인 1개(같은 사이트) → 병원 PC 쿠키(SameSite=Strict)가 그대로 동작
```

- 상태를 바꾸는 일은 **REST**, 서버가 먼저 알려주는 일만 **웹소켓** (실시간 통신 설계 v0.2)
- 세 파트 모두 **TypeScript** → `shared/events.ts`(이벤트 타입)를 같이 씀
- 백엔드·DB는 구급대원 서비스 전용, 일반인 앱과 공유하지 않음 (COR-005)
- 병상 데이터는 **전국 17개 시·도**를 3분마다 수집 (D-104, T-07)
- 앱 서버는 **1대**(v0.11, CR-011). 그래도 서버끼리 공유할 것은 모두 **Redis 또는 DB**에 둠 → 재시작해도 상태가 남고, 나중에 서버를 늘려도 결과가 같음 (D-105, T-08)
- 구급대원·병원 기능은 **한 백엔드**(같은 이송 건을 한 트랜잭션으로 바꿈), 관리자만 **독립 서버** (D-117·118, T-11)
