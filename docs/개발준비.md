## 3. 내 PC 세팅 (모두)

```bash
# 1) 준비물: Node.js 24, Git, Docker Desktop, VS Code(+ESLint·Prettier)
git clone https://github.com/bko0529/savetime.git
cd savetime

# 2) DB·Redis 켜기 (처음 한 번은 schema.sql로 테이블 39개가 만들어짐)
docker compose up -d
docker compose ps        # db healthy, redis running 확인

# 3) 서버 환경 변수
cp server/.env.example server/.env    # 값은 단톡 고정 메시지에서 (절대 커밋 금지)

# 4) 테스트
cd server && npm install && npm test  # 상태 전이 테스트 31개

# 5) 설계 점검 (API·DB를 바꿨을 때)
cd .. && pip install pyyaml && python tools/crosscheck.py
```

DB를 처음 상태로 되돌리려면 `docker compose down -v && docker compose up -d`.

## 4. 작업 규칙

### 4-1. 브랜치·PR
| 규칙 | 예 |
|---|---|
| `main`에 바로 push 금지, 브랜치 → PR → 리뷰 1명 → 합치기 | |
| 브랜치 이름 `파트/스프린트-요구사항-짧은설명` | `server/S1-SFR023-collector`, `app/S2-SFR113-team`, `web/S2-SFR116-pc-login` |
| PR 제목에 요구사항 ID | `[SFR-023] 병상 수집기 (전국 17개, BullMQ)` |
| PR은 작게 (하루치) | 큰 기능은 나눠서 |
| PR 본문은 템플릿 체크리스트 채우기 | `.github/pull_request_template.md` |

### 4-2. 커밋 메시지
```
[파트] 무엇을 했는지 (요구사항 ID)
예) [server] 병상 수집 4곳씩 동시·150초 마감 (SFR-023)
```

### 4-3. 회의
| 언제 | 무엇 |
|---|---|
| 매일 (10분, 단톡도 가능) | 어제 한 것 · 오늘 할 것 · 막힌 것 |
| 스프린트 마지막 날 | 시연(돌아가는 것 보여주기) + 다음 스프린트 확인 + CR 결정 |

### 4-4. "다 됐다"의 기준
1. 인수 기준(Given/When/Then)을 직접 해봤다
2. 테스트가 있고 CI가 통과한다
3. 리뷰를 받았다
4. 요구사항분석서 상태는 그대로 두고, 스프린트 시연에서 보여줬다

### 4-5. 절대 규칙 (README와 같음)
1. API 키는 서버 `.env`에만. 앱·웹에는 SDK 앱 키·JS 키만
2. 환자 이름·주민번호·전화번호·주소는 서버 어디에도 저장 안 함 (일지 초안의 이름·주소는 단말에만)
3. 병원 웹에 요청한 구급대 소속을 보여주지 않음
4. 상태 변경은 반드시 `stateMachine.ts`를 거침
5. 이벤트(웹소켓·푸시)에는 ID·개수·시각만
