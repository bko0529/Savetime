# 시연 (노트북에서, 배포 없이)

2026-11-11 결정: 기말 발표는 **시연 영상**으로 한다. 서버를 Lightsail 에 올리지 않고 노트북에서 DB·서버·병원 웹을 띄우고, 구급대원 앱(진아, Lovable)이 노트북 서버에 붙는다.

2026-11-26 바뀜: **교수님이 직접 사이트에 들어가 써 보며 오류를 찾는 시연**도 한다. 아래 1~3번(노트북에서 켜기)은 그대로 쓰고, 교수님 기기에서 열리게 하는 방법은 [0번](#0-교수님-기기에서-열리게-하기-결정-대기)에서 정한다.

## 0. 교수님 기기에서 열리게 하기 (결정 대기)
지금은 모든 화면이 `localhost` 라 **켠 노트북에서만** 열린다. 교수님 PC·휴대폰에서 열리려면 둘 중 하나가 필요하다 (강욱·승언 결정):

| 방법 | 하는 일 | 링크가 살아 있는 시간 |
|---|---|---|
| 노트북 + 터널 | 노트북에서 켠 서버·웹에 임시 https 주소를 붙인다 (예: Cloudflare Tunnel, **기술정의서에 없는 도구라 팀 확인**) | 노트북이 켜져 있는 동안만 |
| 서버 1대 | `deploy/` 설정으로 Lightsail 1대에 DB·서버·웹을 올린다 | 계속 |

- 어느 쪽이든 병원 웹·서버를 **한 주소**로 묶어야 한다(실시간 연결이 `localhost:4000` 을 찾지 않게). `deploy/app` 의 Caddy 가 그 일을 한다
- 개발 모드(`npm run dev`)는 화면 왼쪽 아래 'N' 배지와 개발용 오류 창이 보이므로 교수님께는 운영 빌드로 보여 준다
- 교수님께 드릴 것: 병원 웹 주소 + 라이선스 키, (관리자 웹을 보여 드리면) 관리자 주소·계정 — 관리자 웹은 허용 IP 에서만 열리고 첫 로그인 때 OTP 앱 연결이 필요하다

## 준비물
| 화면 | 어디서 | 누가 |
|---|---|---|
| 병원 웹 (승인·도착 예정) | 노트북 브라우저 `http://localhost:3000/hospital` | 강욱 |
| 구급대원 앱 2대 (김구조=운전, 이구급=처치) | 휴대폰 2대 또는 휴대폰 1대 + 브라우저 | 진아·승언 |
| 서버·DB | 노트북 | 강욱 |

## 1. 처음 한 번
- **`server/.env` 가 있어야 한다.** 서버는 `node --env-file=.env` 로 켜져서 파일이 없으면 바로 꺼진다. 없으면 강욱에게 받는다 (값은 채팅·문서에 적지 않는다)
- Docker Desktop 을 먼저 켠다 (꺼져 있으면 DB·Redis 가 안 떠서 서버가 Redis 오류로 꺼진다)

```bash
docker compose up -d
```
```bash
docker exec -it $(docker compose ps -q db) psql -U savetime -d savetime -c "CREATE DATABASE savetime_demo"
```
```bash
DATABASE_URL=postgres://savetime:savetime_local@localhost:5432/savetime_demo npm run migrate -w server
```
```bash
DATABASE_URL=postgres://savetime:savetime_local@localhost:5432/savetime_demo npm run demo -w server -- setup
```
- 시연 병원 5곳(천안, 이름에 '(시연)'), 병원 라이선스 키 5개, 대원 계정 2개(`demo-kim`, `demo-lee`)를 만든다
- **키·비밀번호는 이 화면에 한 번만 나온다.** 비밀번호를 정해 두고 싶으면 앞에 `DEMO_PASSWORD=원하는값`(영문+숫자 8자 이상)을 붙인다
- 시연 스크립트는 **이름이 `_demo` 로 끝나는 DB 에서만** 돈다. 개발 DB 를 실수로 지우지 않게 하기 위해서다
- `DATABASE_URL=…` 을 앞에 붙이면 `server/.env` 의 값보다 우선한다. 나머지 설정(키 등)은 `server/.env` 그대로 쓴다

## 2. 켜기 (찍을 때마다)
터미널 3개 (서버 · 병원 웹 · 구급대원 앱). 구급대원 앱은 진아 저장소(`savetime-life-canvas`)를 받아 둔 폴더에서 켠다:
```bash
DATABASE_URL=postgres://savetime:savetime_local@localhost:5432/savetime_demo APP_ORIGINS=http://localhost:8080 npm run dev -w server
```
```bash
NEXT_PUBLIC_SOCKET_ORIGIN=http://localhost:4000 npm run dev -w web
```
```bash
VITE_API_BASE_URL=http://localhost:4000 VITE_FIXED_LAT=36.815 VITE_FIXED_LNG=127.1139 npx vite dev --port 8080
```
- 병원 웹: `http://localhost:3000/hospital` → (처음 한 번) 라이선스 키로 **PC 등록** → **근무 시작** → **알림 켜기**
- `NEXT_PUBLIC_SOCKET_ORIGIN` 이 없으면 병원 웹 실시간 연결이 안 붙어 **알림 켜기**가 눌리지 않는다
- 서버를 껐다 켜면 병원 웹에서 **알림 켜기**를 다시 눌러야 요청이 온다
- 구급대원 앱: `http://localhost:8080` (브라우저 개발자 도구에서 휴대폰 크기로 보면 영상에 좋다). `VITE_FIXED_*` 로 어디서 찍어도 천안 시연 병원 근처로 보이고, 이동 중에는 병원 입구까지 달리는 것을 흉내 낸다
- 병원 PC 를 여러 곳 켜 두려면 병원마다 **다른 브라우저(또는 시크릿 창)** 에서 등록한다. 같은 브라우저는 PC 1대로 본다. 알림 켠 병원이 1곳뿐이면 그 병원이 거절한 뒤 '다시 요청'·'목적지 변경'은 "요청할 병원이 없어요"가 된다
- 김구조·이구급 두 명을 동시에 보려면 브라우저 2개(또는 시크릿 창)나 휴대폰 2대. 같은 브라우저 탭 두 개는 로그인을 같이 쓴다

## 3. 찍기 직전: 초기화
```bash
DATABASE_URL=postgres://savetime:savetime_local@localhost:5432/savetime_demo npm run demo -w server -- reset
```
- 이송 건과 그 기록·알림을 모두 지우고, 병상 값을 '방금 수집'으로 되돌린다 (10분이 지나면 앱에 '갱신 지연'이 뜨므로 찍기 직전에)
- 계정·병원 PC 등록·대원 팀은 남는다. 마지막 줄에 **요청을 받을 수 있는 병원 PC 수**가 나온다. 0이면 병원 웹에서 알림 켜기

## 4. 휴대폰으로 찍고 싶을 때
2번처럼 노트북에서 앱을 띄우면 추가 도구가 필요 없다. 휴대폰 실물로 찍으려면:

| 방법 | 하는 일 | 메모 |
|---|---|---|
| 터널 | 노트북 서버(4000)·앱(8080)에 임시 https 주소를 붙인다 (예: Cloudflare Tunnel) | **기술정의서에 없는 도구라 쓰기 전에 팀 확인** |
| 같은 와이파이 | 휴대폰을 노트북과 같은 와이파이에 두고 `http://노트북IP:8080` | https 가 아니라 위치·알림 권한이 막힐 수 있음 |

- 어느 쪽이든 서버를 켤 때 `APP_ORIGINS` 에 그 앱 주소를, 앱을 켤 때 `VITE_API_BASE_URL` 에 그 서버 주소를 넣는다
- Lovable 미리보기 주소(https)에서 노트북 `localhost` 를 부르면 브라우저가 막는다(로컬 네트워크 접근 차단)

## 병원·관리자 웹 찍을 때 알아 둘 점 (승언, 2026-11-12 리허설 · 11-26 디자인 바꾼 뒤 다시 확인)
화면 모양: **병원 웹은 인계 시안을 바탕으로 한 탭·카드 화면**(`docs/design-handoff-web-ui` 기반, 새 요청 덮개 창 없음), **관리자 웹은 대원 앱 Lovable 시안**과 같다 (PR #111, `web/S8-design-refresh`). main 에 머지되기 전이면 그 브랜치에서 켠다.

**켜기**
- **관리자 웹과 병원 웹은 한 폴더에서 동시에 켤 수 없다.** Next 16 은 같은 `web/` 에서 개발 서버를 하나만 띄운다. 관리자 작업(기능 켜기)을 먼저 하고 끈 뒤 병원 웹을 켠다. 관리자 웹은 `APP_ROLE=admin npm run dev -w web` → `http://localhost:3000/admin`
- **관리자 웹은 새로고침하면 다시 로그인**(비밀번호 + OTP)해야 한다. 토큰을 메모리에만 두는 보안 설계라 그렇고, 로그인 화면에도 이 안내가 있다. 화면 안 위쪽 메뉴로만 움직인다
- 서버가 꺼져 있으면 병원 웹은 '병원 웹을 열지 못했어요' 카드와 **다시 시도** 버튼을 보여 준다. 서버를 켜고 다시 시도를 누른다
- 없는 주소나 병원 서버에서 `/admin` 을 열면 '페이지를 찾을 수 없어요'(404) 화면이 나온다

**병원 웹 흐름**
- **병원 PC 브라우저(Chrome)에서 알림을 '허용'** 해 둔다. 안 하면 화면 위에 노란 안내 상자가 계속 보여 영상에 잡히고, 1280×800 에서는 요청 목록이 아래로 밀린다 (주소창 왼쪽 자물쇠 → 알림 → 허용 → '알림 켜기' 다시)
- 새 요청이 오면 화면을 덮는 창 없이 **왼쪽 요청 카드**가 생기고, 탭 줄 오른쪽에 '새 이송 요청 N건', 알림음 반복·탭 제목 🔴로 알린다. **카드 어디를 눌러도** 오른쪽에 상세가 열린다 (1280px 보다 좁으면 목록 아래). 도착 예정은 위쪽 **도착 예정** 탭
- 상세: 제목 '번호 · 성별 나이대 · 주 증상' + 남은 시간 칩, **환자 평가 정보** 카드(정상 범위 밖은 빨간 글자 + ⚠)와 **우리 병원** 카드(응급실·수술실·중환자실 병상, 도착 예상), 승인 메모, 유효 승인·응급실 병상 안내, **승인(검정)·거절 (사유 선택)(빨강)** 버튼 줄은 화면 아래에 붙어 있다
- 위쪽 막대 오른쪽 **근무 종료**: 한 번 더 묻고 근무를 끝낸다(이 PC 는 더 이상 요청을 받지 않음). 근무 시작 화면으로 돌아간다
- 응급실 빈 병상보다 많이 승인하려 하면 빨간 상자에 이유와 **그래도 승인** 버튼이 나온다 (과승인 경고, SFR-154)
- 확정 뒤 **도착 예정** 표에 내비 남은 시간이 1분마다 바뀌어 보이고, 입구 200m 안에 들어오면 **도착 확인**이 눌린다. 도착 뒤에는 **수용 불가** 버튼
- 대원 앱 위치를 흉내 낼 때 좌표를 몇 초 만에 수백 m 옮기면 **위치 이상치(SFR-040)로 버려져** 도착 확인이 켜지지 않는다. 실제 앱처럼 천천히 다가가야 한다
- 라이선스 키가 30일 안에 끝나면 위쪽에 노란 안내(7일 안이면 빨강)가 뜬다. 시연 키는 setup 뒤 약 76일이라 보통 안 뜬다
- 화면 크기는 1280×800 이상에서 찍는다 (병원 PC 기준). 1024·800px 에서도 화면이 가로로 넘치지는 않는다
- 길찾기 남은 시간(카카오)·병상 수집(공공데이터)은 키가 없어도 시연 값으로 돈다. 카카오 키가 없으면 관리자 **응급실 입구 지정** 창에 지도가 안 뜨고 위도·경도 칸만 나온다

**병원 PC 등록 3대 한도**
- 시연 병원마다 PC 는 **3대까지**다. 브라우저·시크릿 창마다 PC 1대로 세므로 리허설하다 보면 금방 찬다
- 꽉 차면 관리자 웹 **병원 관리 → (병원) PC 보기 → 해제** 로 안 쓰는 PC 를 푼다. `demo reset` 은 PC 등록을 지우지 않는다

**리허설 흔적**
- `demo reset` 은 이송 기록·병상 값만 되돌린다. 리허설하며 만든 계정·키·PC 는 남는다
- 관리자 작업(정지·비밀번호 초기화·키 재발급 등)은 **관리자 작업 이력**에 남고 지울 수 없다(일부러 지울 수 없게 만든 기록). 모니터링 화면에 그대로 보이므로, 시연 DB 에서는 꼭 필요한 관리자 작업만 해 본다
